# おさかな図鑑AI（魚の写真判定）

「おさかな図鑑」（`/line-menu/fish`）は、魚の写真から、近い魚を3つ表示します。
**判定は、利用者のブラウザの中だけで行います。写真は外部へ送信しません**（サーバーに送らない・外部のAIサービスを使わない）。

## 1. 仕組み

| 項目 | 内容 |
|---|---|
| モデル | EfficientNet-B0（約16MB、ONNX形式）。`public/models/fish/fish-s75-v1.onnx` |
| 対応する魚 | 沖縄の魚 **75種**（`src/lib/fish/speciesData.json`、記録の多い順） |
| 実行環境 | ブラウザの WebAssembly（`onnxruntime-web`）。`public/ort/` に、ビルドの前にコピーする（`scripts/copy-ort.mjs`、Git管理外） |
| 入力 | 写真の短い辺を293pxにそろえ、中央256×256を切り出し、ImageNetの平均・標準偏差で正規化 |
| 出力 | 75種それぞれの確率。上位3つを表示。1位が50%未満なら「自信がありません」と表示 |
| 毒・とげの注意 | 魚の名前による簡易の表示（ミノカサゴ・アイゴ・モンガラの仲間など）。**正確な安全情報ではない** |

前処理（`src/lib/fish/classify.ts` の数値）は、学習のときと同じ手順にしている。変えると精度が落ちる。

## 2. 精度（最終テスト）

最終テストは、**学習に使っていない、2025年7月以降に撮影された写真**（593枚、75種）で、1回だけ測った。

| | 1位が正解 | 上位3つに正解 |
|---|---|---|
| **本モデル（75種）** | **93.1%** | **97.3%** |
| 自信70%以上だけ答える場合 | 回答91%、正解率 98.1% | |
| 参考: 大きなモデル BioCLIP 2（学習なし、50種） | 96.0% | 98.5% |

**限界**
- テスト写真は、iNaturalist のきれいな写真。**水中の暗い・ぶれた・遠い写真では、これより下がる可能性が高い**。実際の撮影写真での評価は未実施。
- 対応する75種以外の魚を撮ると、近い別の魚の名前が出ることがある（自信が低くなりやすいので、警告を出す）。
- 毒・とげの注意は、名前による簡易判定で、網羅していない。

## 3. 学習データとライセンス（重要）

- 学習用の写真は、**iNaturalist の公開API**から集めた、**沖縄ほか世界各地の研究グレード（利用者どうしで種類が確認された）観察写真**（約1.9万枚、75種）。
- 写真の撮影者・ライセンス・出典は、学習時の記録（`train_meta2.json`、Git管理外）に残している。
- **ライセンスの内訳**: 約88%が **非商用限定（CC BY-NC 系）**。ほかに CC BY、CC BY-SA、CC0 など。**改変禁止（ND）の写真が約1,100枚**含まれる。
- 先生モデルとして、BioCLIP 2（Hugging Face `imageomics/bioclip-2`、MIT ライセンスと表記）の判定結果を使った（蒸留）。
- したがって、**このモデルは、授業・学習目的の非商用での利用を前提にしている。営利目的で使うときは、使えない**。商用にするには、ライセンスが明確な写真だけで学習し直す必要がある。
- 写真そのものは、このリポジトリに含めていない（モデルの重みだけを含む）。

## 4. モデルの作り方（再現手順）

スクリプトは `ml/fish/` にある。実行には、Python 3.13、PyTorch（CUDA 対応を推奨）、`open_clip_torch`、`onnxruntime`、`onnx` が必要。

1. **種のリスト**: iNaturalist API の `species_counts`（沖縄、条鰭綱、研究グレード）で、記録の多い順に75種を選ぶ。干潟・淡水の魚（ミナミトビハゼ、クロヨシノボリ、オオウナギ、オオクチユゴイ）は除く。
2. **写真を集める**（`collect_*.py`）: 学習用は2025年6月以前、最終テスト用は2025年7月以降（日付で分け、混ざらない）。同じ撮影者の写真は1種につき最大6枚。許諾のある写真だけ。
3. **先生のラベル付け**（`soft_labels.py`）: BioCLIP 2 が、写真ごとに75種の近さ（ロジット）を付ける。
4. **学習**（`train2.py`）: 撮影者ごとに検証用を分け、正解ラベル＋先生の答え方（蒸留）で学習。
5. **ONNX に変換**（`export75.py`）し、変換の前後で答えが一致することを確かめる。
6. **最終テスト**（`final_test.py`）は、モデルを選んだあとに、1回だけ測る。

モデルを差し替えるときは、`MODEL_URL`（`src/lib/fish/classify.ts`）のファイル名のバージョンを変える（ブラウザが1年間キャッシュするため）。

## 5. 配信上の注意

- モデル（約16MB）と実行用ファイル（約15MB）は、**初回の表示で合計約30MBを読み込む**（以降はブラウザのキャッシュ）。モバイル回線では、読み込みに時間がかかる。
- LINEアプリ内のブラウザでの動作は、未確認（WebAssembly に対応した、新しい OS・ブラウザが前提）。

## 6. コレクション（撮った魚の記録）

判定した写真を、「コレクション」に追加できる（`/line-menu/fish/collection`）。

| 項目 | 内容 |
|---|---|
| 見せ方 | **図鑑**（対応する75種のマス目。見つけた魚は写真つき、まだの魚は「？？？」。「◯ / 75種」の進み具合）と、**アルバム**（撮った写真の一覧・詳細・削除） |
| 追加のしかた | 判定の結果の下で、追加する魚を選ぶ（初期値は判定の1位。2位・3位、「わからない」、ほかの魚への選び直しもできる） |
| 保存先 | **その端末のブラウザの中だけ**（IndexedDB）。サーバーには送らない。費用もかからない |
| 見られる人 | その端末を使っている本人だけ。ショップのスタッフにも見えない |
| 写真 | 長い辺を960px以内のJPEGに**縮小して書き直して**保存する。**撮影場所などの情報（EXIF）は残らない** |
| 上限 | 150枚（端末の容量を使い切らないため）。上限に達したら、古い写真を削除してから追加する |

**限界（利用者にも画面で伝えている）**
- ブラウザのデータを消した、別の端末・別のブラウザ（LINEの中と通常のブラウザなど）で開いた、プライベートブラウズを使っている、の場合は、コレクションが**見えない・保存できない**。
- 端末の容量が足りなくなると、ブラウザが保存を消すことがある。追加のとき、消されにくくなるよう、ブラウザにお願い（`navigator.storage.persist()`）はするが、認められるとは限らない。
- お客さんにログインの仕組みがないため、サーバーに保存して端末をまたいで見られるようにはしていない（やるには、LINEログインなどの本人確認と、写真の保存先・個人情報の管理が必要）。

実装: `src/lib/fish/collection.ts`（検証・進み具合などの純粋な処理）、`collectionStore.ts`（IndexedDB）、`downscalePhoto.ts`（縮小）。

## 7. マイ水槽（集めた魚を泳がせる）

コレクションの魚を、画面の水槽で泳がせる遊び（`/line-menu/fish/aquarium`）。

- **動き**: キャンバスに描く。魚は泳ぎ、壁で向きを変える。水をタップするとエサがまかれ、近い魚が食べにくる。魚をタップすると名前が出る。「動きを減らす」設定の端末では、ゆっくり動く。動きの計算は `src/lib/fish/aquariumSim.ts`（画面に依存しない関数。テストあり）。
- **泳ぐ姿**: 魚だけを切り抜いた画像、または、写真を丸い泡で包んだもの。**どちらにするかは、追加するときに利用者が選ぶ**（`SpriteChooser`）。コレクションの写真の詳細から、あとで選び直せる。選ばなかった写真・切り抜けなかった写真は、泡で泳ぐ。
  - 水槽を開いたときに、自動で切り抜くことはしない（時間がかかるため）。
- **切り抜き**: 小さな「目立つものを見つける」AI（U²-Netp, **Apache License 2.0**、4.4MB、`public/models/fish/u2netp-v1.onnx`）を、ブラウザの中で動かす（`src/lib/fish/browserCutout.ts`）。写真は外へ送らない。
- **限界**: 水中の写真は背景が複雑で、魚が小さいと、**魚ではなくサンゴなどを切り抜くことがある**（ミノカサゴの写真で確認）。そのため、切り抜きを自動で採用せず、利用者に見てもらう。目安として、切り抜きを魚の判定AIにかけ直し、元の判定と食い違えば「疑わしい」と警告して、初期選択を「泡」にする（`judgeCutout`）。この目安は完全ではない（正しい切り抜きでも警告が出ることがある）。
- **保存**: 切り抜きは、コレクションの記録（IndexedDB）の `sprite` に、PNGで保存する。`null` は「泡で泳ぐ」、未設定も泡。
- **確認した範囲**: 実ブラウザ（Chromium）での動作。LINEアプリ内のブラウザでの動作は、未確認。
