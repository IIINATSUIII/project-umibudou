# 店舗スマホからPCへの受付引き継ぎ

## 実装計画
- ブランチ: codex/mobile-checkin-handoff（開始点 feature/google-forms-booking-import）
- スマホ /checkin/mobile はスタッフ認証後、QRだけを読み取り氏名と送信結果を表示する。
- /api/checkin-handoff は当日・未使用・有効期限内・有効な予約のQRのみを受け付ける。送信しても受付は確定しない。
- 店舗共通の受付待ちを永続保存し、PC /questionnaire/scan が5秒間隔（Sheetsは15秒）で取得する。PC台数未確定のため特定端末へのペアリングは行わない。
- PCは対象者を選択し最新の問診を取得する。既存の問診確認と名簿追加を使い、受付方法はQR読取とする。
- PostgreSQL / Sheets / ローカルJSONの既存構成を維持する。公開QR APIやLINEメニューの契約は変更しない。

## 受入条件・検証
- 未認証アクセスと別オリジンからの更新を拒否する。
- 期限切れ、使用済み、キャンセル、当日以外のQRを拒否し、重複送信で受付待ちが増えない。
- スマホへの応答に健康情報を含めない。QR文字列をURL・ログ・受付待ちストアに保存しない。
- スマホのカメラ停止・画面離脱・通信失敗からの再送を扱う。
- 受付後に一覧から消え、既存の手動検索を維持する。
- 独立サブエージェントレビュー、必要な修正、テスト・型チェック・lint・build、ローカル画面確認。

## 運用
- スマホとPCで同じ公開HTTPSサイトにスタッフとしてログインする。スマホは /checkin/mobile をブックマークする。
- 受付待ちは店舗で共有する。複数PCで同じ人を開けるため受付確定時のサーバー検証を正とする。
- iPhone/Android実機のカメラと本番データストアは公開前の確認が必要。
- 本変更に本番反映・外部送信・マイグレーション実行は含めない。


## レビュー結果
独立サブエージェントのレビューと再レビューを実施。以下4件を修正し、最終差分で新たな修正必須指摘なし。
- Sheetsポーリング頻度を15秒へ延長し、APIから適切な間隔を返す。
- URLの初期検索を一度だけにし、受付成功後の表示を上書きしない。
- カメラ起動ごとにvideo要素を分離し、遅れて終了した旧セッションによる停止を防ぐ。
- 選択操作の世代を管理し、古い問診取得の応答で別人の表示を上書きしない。
