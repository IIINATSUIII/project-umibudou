# 問診の入力資格と受付資格（I03）

基準: main `dd585d2`（PR #49統合後）。#38 / #40 / #41 / #43 / #44 / #48 を追加統合する際も、この契約を保持する。

| 用途 | 契約 |
| --- | --- |
| 入力URL | `/questionnaire/{accessToken}`。値は予約の `questionnaireToken` |
| 公開送信 | `POST /api/public/questionnaires` の `accessToken` |
| 公開再表示 | `GET /api/public/questionnaires?accessToken=...` |
| 入力URL期限 | 予約の `questionnaireTokenExpiresAt`。保存期限と現在のダイブ日の翌日0時JSTの両方を確認 |
| 発行・再発行 | スタッフ認証下の `POST /api/reservations/questionnaire-url`、`{ id, reissue?: boolean }` |
| 明示失効 | 同URLの `DELETE`、`{ id }`。入力トークンと期限を空にする |
| 受付資格 | 問診票の独立した `qrToken`。QRにこの値だけを格納。`qrExpiresAt` / `qrUsed` で受付可能性を判定 |

公開APIは `body.token`、`reservationId`、`qrToken` を入力資格として扱わない。予約IDは入力トークンからサーバーで決める。スタッフ用POSTの `reservationId` はログイン後の業務指定であり、公開APIの代替認証ではない。

入力URLはキャンセル・返金済み、期限未設定、不正期限、期限と同時刻以降、現在のダイブ日が過ぎた場合に無効。過去日への予約変更でも古い将来期限だけではアクセスできない。発行・再発行・失効と提出は既存の `withStoreWriteLock` を利用する。

再発行すると旧入力URLは無効。入力URLの再発行・失効は、保存済みの回答・同意・受付QRを書き換えない。キャンセルされた予約の受付は拒否する。受付済み／期限切れQRの公開再表示・公開再送には410を返す。スタッフの過去回答閲覧は別の認証済み機能として維持する。

トークン生成、入力資格判定、受付QRの有効性判定は `src/lib/questionnaireToken.ts` に集約。閲覧は必要最低限の完了情報だけを返し、健康情報は公開しない。完了応答は `Cache-Control: no-store`。

旧データの `questionnaireExpiresAt` は保存層の `normalizeReservation` が `questionnaireTokenExpiresAt` に読み替える。この互換性を公開APIの資格名の別名受理に拡張しない。期限のない旧入力URLはスタッフが再発行する。移行・保存形式はmainの `storeSchema.ts` を維持し、他PRの列追加をそのまま重ねない。

検証: `npm test` の `questionnaireAccess.test.ts` で資格混同、再発行・失効、キャンセル、期限境界、日付変更、QR使用済み、受付画面の認証を確認する。共通の同意検証・保存再試行・破損ファイル保護は `questionnaireSubmission.test.ts` / `localStore.test.ts` で確認する。
