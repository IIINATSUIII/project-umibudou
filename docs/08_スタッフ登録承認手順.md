# スタッフ登録 手順書

## 1. 初回セットアップ（管理者のみ）

1. `.env.local` に以下を設定する。

```env
DATABASE_URL=postgresql://ユーザー:パスワード@ホスト:5432/データベース
SESSION_SECRET=ランダムな長い文字列
STAFF_CREDENTIALS=admin@example.com:初期パスワード
STAFF_ADMIN_EMAIL=admin@example.com
RESEND_API_KEY=re_...
EMAIL_FROM=沖ダイブ・パートナー <noreply@example.com>
APP_BASE_URL=https://example.com
```

2. 依存関係をインストールする。

```bash
npm ci
```

3. PostgreSQLへ認証テーブルを作成する。

```bash
npm run db:migrate
```

4. 初期管理者のメールアドレスとパスワードで一度ログインする。

初回ログイン時に、`STAFF_CREDENTIALS` のアカウントがパスワードハッシュ付きでDBへ移行されます。

5. 動作確認後、本番環境から `STAFF_CREDENTIALS` を削除する。

`RESEND_API_KEY` と `EMAIL_FROM` を設定すると、管理者がアカウントを承認したときに、本人の登録メールアドレスへ案内メールを送信します。`EMAIL_FROM` はResendで認証済みの送信元ドメインを指定してください。`APP_BASE_URL` はメール内のログインリンクに使います。

## 2. スタッフがアカウントを作成する

1. ログイン画面（`/login`）を開き、「アカウント作成」タブを選ぶ。
2. 氏名とメールアドレスを入力する。
3. 5文字以上のパスワードを入力し、確認欄にも同じパスワードを入力する。
4. 「アカウントを作成」を押す。

登録すると「管理者が承認するとログインできるようになります」と表示されます。この時点ではまだログインできません。権限は常に「スタッフ」で、登録画面から管理者権限は選べません。

同じ送信元からの登録は1時間に5回までです。すでに登録済みのメールアドレスでも、画面には同じ「受け付けました」が表示されます（登録の有無を外部から調べられないようにするため）。

## 3. 管理者が承認する

1. 管理者でログインする。
2. 上部メニューの「スタッフ管理」を開く。
3. 「承認待ち」欄で、氏名とメールアドレスが本人のものか確認する。
4. 「承認」を押す。

承認するとスタッフとしてログインできるようになります。Resendが設定済みなら、本人の登録メールアドレスへ承認の案内メール（登録メールアドレスとログインURL）を送信します。メール設定が未完了または送信に失敗した場合でも承認は完了し、画面に「本人へ伝えてください」と表示されます。パスワードは安全上メール送信しません。

覚えのない登録は承認しないでください。承認待ちのアカウントはログインできないため、そのままにしておいても業務データは見られません。

管理者権限を渡したい場合は、承認後に「登録済みスタッフ」欄で権限を「管理者」に変更します。

## 4. スタッフを停止・再開する

1. 管理者で「スタッフ管理」を開く。
2. 対象スタッフの「停止」または「再開」を押す。

停止すると、そのスタッフの既存セッションも無効になります。最後に残った有効な管理者は停止できません。承認待ち・停止中のアカウントでログインすると「管理者の承認待ち、または利用停止中です」と表示されます。

## 5. 確認ポイント

- 招待リンクは廃止した。誰でもログイン画面からアカウントを作成できるが、管理者が承認するまでログインできない。
- 登録時の権限は常にスタッフ。管理者権限は既存の管理者がスタッフ管理画面で付与する。
- パスワードは平文で保存されない。
- スタッフ登録と承認にはPostgreSQLが必要。
- 承認メールはResend設定時に送信される。登録申請の時点ではメールを送らない。
