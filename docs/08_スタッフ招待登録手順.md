# スタッフ登録 手順書

## 1. 初回セットアップ（管理者のみ）

1. `.env.local` に以下を設定する。

```env
DATABASE_URL=postgresql://ユーザー:パスワード@ホスト:5432/データベース
SESSION_SECRET=ランダムな長い文字列
STAFF_CREDENTIALS=admin@example.com:初期パスワード
STAFF_ADMIN_EMAIL=admin@example.com
RESEND_API_KEY=re_...
EMAIL_FROM=沖ダイブ・パートナー <noreply@example.com>
APP_BASE_URL=https://example.com
```

2. 依存関係をインストールする。

```bash
npm ci
```

3. PostgreSQLへ認証テーブルを作成する。

```bash
npm run db:migrate
```

4. 初期管理者のメールアドレスとパスワードで一度ログインする。

初回ログイン時に、`STAFF_CREDENTIALS` のアカウントがパスワードハッシュ付きでDBへ移行されます。

5. 動作確認後、本番環境から `STAFF_CREDENTIALS` を削除する。

`RESEND_API_KEY` と `EMAIL_FROM` を設定すると、スタッフ登録完了時に登録メールアドレスへ案内メールを送信します。`EMAIL_FROM` はResendで認証済みの送信元ドメインを指定してください。`APP_BASE_URL` はメール内のログインリンクに使います。

## 2. 招待リンクを発行する

1. 管理者でログインする。
2. 上部メニューの「スタッフ管理」を開く。
3. 招待するスタッフのメールアドレスと権限を入力する。
4. 「招待リンクを作成」を押す。
5. 表示されたリンクを、本人だけが見られる安全な経路で共有する。

招待リンクの有効期限は24時間です。同じメールアドレスへの有効な招待は重複発行できません。

## 3. 招待されたスタッフが登録する

1. 共有された招待リンクを開く。
2. 招待されたメールアドレスが表示されていることを確認する。
3. 氏名を入力する。
4. 5文字以上のパスワードを入力し、確認欄にも同じパスワードを入力する。
5. 「アカウントを作成」を押す。

登録が完了するとログイン画面へ移動します。登録したメールアドレスとパスワードでログインしてください。招待リンクは登録後に再利用できません。

Resendが設定済みなら、登録したメールアドレスへ登録完了メールも送信されます。メールには登録メールアドレスとログインURLを記載します。メール設定が未完了または送信に失敗した場合でもアカウント作成は完了し、ログイン画面に警告が表示されます。パスワードは安全上メール送信しません。

## 4. スタッフを停止・再開する

1. 管理者で「スタッフ管理」を開く。
2. 対象スタッフの「停止」または「再開」を押す。

停止すると、そのスタッフの既存セッションも無効になります。最後に残った有効な管理者は停止できません。

## 5. 招待を取り消す

登録前の招待は「有効な招待」欄から「取り消す」を押します。取り消し後のリンクでは登録できません。

## 6. 確認ポイント

- スタッフ登録には有効な招待リンクが必要。
- 招待の権限は登録画面で変更できない。
- パスワードは平文で保存されない。
- スタッフ登録と招待にはPostgreSQLが必要。
- 招待リンク自体のメール自動送信は未実装のため、管理者がリンクを共有する。登録完了メールはResend設定時に送信される。
