# PR #43 — 現行契約への統合と移行保護

旧PRのフォーム・公開API・スキーマは、#49・#51で統合済みの現行mainへ合わせた。#55の月末日フィルタ修正も含め、既存履歴を保ったマージで競合を解消する。mainに対する追加変更は、Sheets移行の別名項目の矛盾検知と回帰テストに絞る。

## 移行時の動作

- `POST /api/setup` は問診シートを先に読み、高血圧、体調詳細、睡眠、ダイブ経験、同意日時、スタッフ確認、Cカードの新旧項目名を比較する。
- 両方に値があり矛盾する場合、予約を含む全シートの移行・バックアップ作成を始める前に停止する。現行ヘッダーに旧名列が併存する場合も検査する。
- booleanの表記差、文字列の前後空白、既知の睡眠区分の表記差は同じ意味として扱う。比較で空白を無視しても保存する文字列は変更しない。高血圧・Cカード有無の未知booleanはfalseへ変換せず拒否する。
- 追加された新列が空で旧列に値がある場合は、旧値を新列へ引き継ぐ。未知列は保持し、ヘッダーのない列に値がある場合は停止する。空の旧Cカード区分で既存の資格を上書きしない。
- 旧`cCardStatus`列はバックアップ後に`hasCCard`・`cCardType`へ移し、稼働シートから除く。通常の読取で旧区分が再度資格を上書きするのを防ぐ。その他の未知列と、現行互換列は保持する。
- エラーにはシートの行番号と項目名だけを含め、入力された健康情報・個人情報の値を含めない。
- 矛盾した行は、書き込みを停止してバックアップと照合し、元シートの値を管理者が確認・修正した後、セットアップを再実行する。

検査は明示的なSheets移行に限定する。通常の問診送信・読み取り・受付、JSONストア、PostgreSQL取込の動作には追加の拒否条件を入れない。

「初めて」と総本数の組み合わせの追加制約は仕様に明記がないため、この変更には含めない。実Sheets・本番データの移行は未実施。
